# DBMS Fundamentals

## 1) What is DBMS?

**DBMS (Database Management System)** is software used to store, organize, retrieve, and manage data efficiently.

### Why DBMS is used
- Reduces data duplication
- Improves data consistency
- Controls secure access to data
- Supports backup and recovery
- Enables concurrent multi-user access

### Common DBMS examples
- MySQL
- PostgreSQL
- Oracle Database
- SQL Server
- MongoDB (NoSQL DBMS)

---

## 2) RDBMS vs NoSQL

| Feature | RDBMS | NoSQL |
|---|---|---|
| Data model | Tables (rows/columns) | Document, key-value, column-family, graph |
| Schema | Fixed/structured | Flexible or schema-less |
| Query language | SQL | Varies by database |
| Transactions | Strong ACID support | Often eventual consistency (depends on DB) |
| Scaling | Vertical (traditionally) | Horizontal (commonly) |
| Best for | Structured business data | High-scale, rapidly changing/unstructured data |

### Quick examples
- **RDBMS use case:** Banking, payroll, ERP
- **NoSQL use case:** Real-time analytics, social feeds, IoT events

---

## 3) Schema

**Schema** is the logical blueprint of a database.

It defines:
- Table names
- Column names and data types
- Constraints (primary key, unique, not null, foreign key)
- Relationships between tables

### Example schema (simple)
```sql
CREATE TABLE Department (
	department_id INT PRIMARY KEY,
	department_name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE Employee (
	employee_id INT PRIMARY KEY,
	employee_name VARCHAR(100) NOT NULL,
	department_id INT,
	FOREIGN KEY (department_id) REFERENCES Department(department_id)
);
```

## 4) Tables, Rows, Columns

- **Table:** Collection of related data (like a sheet)
- **Row (Record/Tuple):** One complete entry in a table
- **Column (Field/Attribute):** One property of the data

### Example

Table: `Student`

| student_id | student_name | age |
|---|---|---|
| 101 | Ravi | 20 |
| 102 | Priya | 21 |

- `Student` → table
- `101, Ravi, 20` → one row
- `student_name` → one column

## 5) Keys in DBMS

Keys help uniquely identify records and build relationships.

### 5.1 Primary Key

A **Primary Key** uniquely identifies each row in a table.

Rules:
- Must be unique
- Cannot be `NULL`
- One primary key per table (can be composite)

```sql
CREATE TABLE Student (
	student_id INT PRIMARY KEY,
	student_name VARCHAR(100)
);
```

### 5.2 Foreign Key

A **Foreign Key** is a column in one table that refers to the primary key of another table.

Purpose:
- Maintains referential integrity
- Prevents invalid related data

```sql
CREATE TABLE Orders (
	order_id INT PRIMARY KEY,
	customer_id INT,
	FOREIGN KEY (customer_id) REFERENCES Customer(customer_id)
);
```

### 5.3 Candidate Key

A **Candidate Key** is any column (or set of columns) that can uniquely identify a row.

- A table can have multiple candidate keys
- One candidate key is chosen as the primary key

Example in `Employee` table:
- `employee_id`
- `email`

Both can uniquely identify a row, so both are candidate keys.

### 5.4 Composite Key

A **Composite Key** uses two or more columns together to uniquely identify a row.

```sql
CREATE TABLE Enrollment (
	student_id INT,
	course_id INT,
	enrollment_date DATE,
	PRIMARY KEY (student_id, course_id)
);
```

Here, uniqueness is guaranteed by the combination `(student_id, course_id)`.

### 5.5 Unique Key

A **Unique Key** ensures all values in a column are unique.

- Usually allows `NULL` (DB-dependent)
- Multiple unique keys can exist in one table

```sql
CREATE TABLE UserAccount (
	user_id INT PRIMARY KEY,
	email VARCHAR(150) UNIQUE,
	phone VARCHAR(20) UNIQUE
);
```

### 5.6 Surrogate Key

A **Surrogate Key** is an artificial/system-generated key with no business meaning.

Examples:
- Auto-increment integer
- UUID

```sql
CREATE TABLE Product (
	product_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
	product_code VARCHAR(50) UNIQUE,
	product_name VARCHAR(100) NOT NULL
);
```

`product_id` is surrogate, while `product_code` can be a natural/candidate key.

---

## 6) Primary Key vs Unique Key (Quick Difference)

| Feature | Primary Key | Unique Key |
|---|---|---|
| Uniqueness | Yes | Yes |
| NULL allowed | No | Usually yes (depends on DB) |
| Count per table | One primary key | Multiple unique keys |
| Purpose | Main row identifier | Enforce uniqueness on alternate columns |

## 7) Real-Time Mini Example (E-commerce)

```sql
CREATE TABLE Customer (
	customer_id INT PRIMARY KEY,
	email VARCHAR(120) UNIQUE,
	full_name VARCHAR(120) NOT NULL
);

CREATE TABLE Product (
	product_id INT PRIMARY KEY,
	sku VARCHAR(60) UNIQUE,
	product_name VARCHAR(120) NOT NULL
);

CREATE TABLE OrderItem (
	order_id INT,
	product_id INT,
	quantity INT NOT NULL,
	PRIMARY KEY (order_id, product_id),
	FOREIGN KEY (product_id) REFERENCES Product(product_id)
);
```

Concepts used:
- `customer_id`, `product_id` → primary keys
- `email`, `sku` → unique keys
- `(order_id, product_id)` → composite key
- `product_id` in `OrderItem` → foreign key

---

## 8) Summary

- DBMS manages data efficiently with security and consistency.
- RDBMS uses structured tables and SQL; NoSQL offers flexible models for scale.
- Schema defines structure and constraints.
- Keys are central to integrity and relationships:
	- Primary key, foreign key, candidate key
	- Composite key, unique key, surrogate key

These are the core fundamentals required to build a strong base in databases.
