# Docker Container Workarounds

## Image Authentication

### Pulling Images
```bash
docker pull IMAGE_NAME
```
✅ **No login required** to pull images from public registries.

### Pushing Images
```bash
docker login
docker push REGISTRY/IMAGE_NAME:TAG
```
⚠️ **Login required** before pushing images. Use `docker login` to authenticate.

---

## Running Containers

### Issue: Container Fails to Start

**❌ Wrong way:**
```bash
docker run --name c1 image_id
```
This will fail and the container won't respond to input.

**✅ Correct way:**
```bash
docker run -it --name c1 image_id
```

The `-it` flags are essential:
- **`-i`** (--interactive) - Keep STDIN open even if not attached
- **`-t`** (--tty) - Allocate a pseudo-terminal

---

## Accessing the Container

### Login to Container Shell
```bash
docker exec -it CONTAINER_ID /bin/bash
```

**Important:**
- The `-it` flags are **required** to access the interactive shell
- Without `-it`, you cannot login inside the container
- `/bin/bash` may vary depending on the image type (try `/bin/sh` if bash is unavailable)

### Run Command Without Container Login
```bash
docker exec CONTAINER_ID "COMMAND"
```

**Note:** Use this when you only need to execute a specific command without opening an interactive shell.

## Quick Reference

| Task | Command | Notes |
|------|---------|-------|
| Pull image | `docker pull IMAGE_NAME` | No login needed |
| Push image | `docker push IMAGE_NAME` | Login required |
| Run container | `docker run -it --name NAME IMAGE_ID` | `-it` is essential |
| Access shell | `docker exec -it CONTAINER_ID /bin/bash` | `-it` required for interactive access |
| Execute command | `docker exec CONTAINER_ID "COMMAND"` | No interactive shell needed |
