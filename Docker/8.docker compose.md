## Introduction

Docker Compose is a tool for defining and running multi-container Docker applications. It uses a YAML file to configure application services, networks, and volumes, enabling you to start all services with a single command.

### Why Docker Compose?
- **Single Command Deployment** - Launch entire application stack with `docker-compose up`
- **Service Definition** - Define all services in one YAML file
- **Networking** - Automatic network creation for service communication
- **Volume Management** - Easy data persistence configuration
- **Environment Isolation** - Multiple isolated environments on one machine
- **Development Simplification** - No need to remember complex Docker run commands

## Installation

### Windows & macOS
```bash
# Docker Desktop includes Docker Compose v2
# Verify installation
docker compose version

# Output:
# Docker Compose version v2.20.3
```

### Linux
```bash
# Install Docker Compose v2
sudo apt-get update
sudo apt-get install -y docker-compose-plugin

# Verify installation
docker compose version

# For Docker Compose v1 (older)
sudo curl -L "https://github.com/docker/compose/releases/download/1.29.2/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
docker-compose --version
```

## Important Features

### 1. **Multi-Container Orchestration**
- Define multiple services in a single file
- Automatic startup and shutdown sequence
- Service dependency management

### 2. **Environment Variables**
- `.env` file support for configuration
- Variable interpolation in compose files
- Easy environment-specific configurations

### 3. **Automatic Networking**
- Services communicate using service names as hostnames
- Isolated bridge network created automatically
- No need to expose all ports

### 4. **Volume Management**
- Named volumes for data persistence
- Bind mounts for local development
- Volume sharing between containers

### 5. **Service Scaling**
- Scale specific services to multiple instances
- Load balancing between replicas
- Easy horizontal scaling

### 6. **Health Checks**
- Define service health checks
- Automatic restart on failure
- Monitor container status

### 7. **Dependency Management**
- Control service startup order
- `depends_on` for service relationships
- Wait conditions for readiness

### 8. **Override Configurations**
- `docker-compose.override.yml` for local overrides
- Environment-specific compose files
- Easy development-production separation

### 9. **Restart Policies**
- Automatic restart on failure
- Configurable restart conditions
- Maximum retry attempts

### 10. **Resource Limits**
- CPU limits and reservations
- Memory limits and swaps
- Device access control

## Compose File Structure

### Basic Structure (Version 3.8)

```yaml
version: '3.8'

services:
  service-name:
    image: image-name:tag
    container_name: container-name
    ports:
      - "host-port:container-port"
    environment:
      - KEY=VALUE
    volumes:
      - volume-name:/container-path
    networks:
      - network-name
    depends_on:
      - other-service
    restart: policy

volumes:
  volume-name:
    driver: local

networks:
  network-name:
    driver: bridge
```

## Practical Examples

### Example 1: Simple Web Application with Database

#### docker-compose.yml
```yaml
version: '3.8'

services:
  web:
    image: nginx:latest
    container_name: web-server
    ports:
      - "80:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - db
    networks:
      - app-network
    restart: unless-stopped
    environment:
      - TZ=UTC

  db:
    image: mysql:8.0
    container_name: mysql-db
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: appdb
      MYSQL_USER: appuser
      MYSQL_PASSWORD: apppass123
    volumes:
      - db-data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - app-network
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  db-data:
    driver: local

networks:
  app-network:
    driver: bridge
```

#### Commands
```bash
# Start services
docker compose up -d

# View running services
docker compose ps

# Output:
# NAME              COMMAND                  SERVICE   STATUS      PORTS
# web-server        "nginx -g daemon off"    web       Up 2 mins   0.0.0.0:80->80/tcp
# mysql-db          "docker-entrypoint..."   db        Up 2 mins   3306/tcp

# Stop services
docker compose down

# Stop and remove volumes
docker compose down -v
```

### Example 3: Microservices Architecture

#### docker-compose.yml
```yaml
version: '3.8'

services:
  # API Gateway
  api-gateway:
    image: api-gateway:latest
    container_name: api-gateway
    ports:
      - "8000:8000"
    environment:
      - STATS_SERVICE_URL=http://stats-service:5001
      - USER_SERVICE_URL=http://user-service:5002
      - ORDERS_SERVICE_URL=http://orders-service:5003
    depends_on:
      - stats-service
      - user-service
      - orders-service
    networks:
      - microservices-network
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 15s
      timeout: 5s
      retries: 3

  # Stats Service
  stats-service:
    image: stats-service:latest
    container_name: stats-service
    environment:
      - DATABASE_URL=postgresql://statsuser:statspass@stats-db:5432/stats
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      - stats-db
      - redis
    networks:
      - microservices-network
    restart: unless-stopped
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 512M
        reservations:
          cpus: '0.25'
          memory: 256M

  # User Service
  user-service:
    image: user-service:latest
    container_name: user-service
    environment:
      - DATABASE_URL=postgresql://useruser:userpass@user-db:5432/users
    depends_on:
      - user-db
    networks:
      - microservices-network
    restart: unless-stopped

  # Orders Service
  orders-service:
    image: orders-service:latest
    container_name: orders-service
    environment:
      - DATABASE_URL=postgresql://ordersuser:orderspass@orders-db:5432/orders
      - KAFKA_BROKERS=kafka:9092
    depends_on:
      - orders-db
      - kafka
    networks:
      - microservices-network
    restart: unless-stopped

  # Databases
  stats-db:
    image: postgres:13-alpine
    container_name: stats-db
    environment:
      POSTGRES_USER: statsuser
      POSTGRES_PASSWORD: statspass
      POSTGRES_DB: stats
    volumes:
      - stats-db-data:/var/lib/postgresql/data
    networks:
      - microservices-network
    restart: unless-stopped

  user-db:
    image: postgres:13-alpine
    container_name: user-db
    environment:
      POSTGRES_USER: useruser
      POSTGRES_PASSWORD: userpass
      POSTGRES_DB: users
    volumes:
      - user-db-data:/var/lib/postgresql/data
    networks:
      - microservices-network
    restart: unless-stopped

  orders-db:
    image: postgres:13-alpine
    container_name: orders-db
    environment:
      POSTGRES_USER: ordersuser
      POSTGRES_PASSWORD: orderspass
      POSTGRES_DB: orders
    volumes:
      - orders-db-data:/var/lib/postgresql/data
    networks:
      - microservices-network
    restart: unless-stopped

  # Cache
  redis:
    image: redis:7-alpine
    container_name: redis-cache
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    networks:
      - microservices-network
    restart: unless-stopped
    command: redis-server --appendonly yes

  # Message Queue
  kafka:
    image: confluentinc/cp-kafka:7.3.0
    container_name: kafka-broker
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    depends_on:
      - zookeeper
    networks:
      - microservices-network
    restart: unless-stopped

  zookeeper:
    image: confluentinc/cp-zookeeper:7.3.0
    container_name: zookeeper
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
    networks:
      - microservices-network
    restart: unless-stopped

volumes:
  stats-db-data:
  user-db-data:
  orders-db-data:
  redis-data:

networks:
  microservices-network:
    driver: bridge
```

### Example 4: Development Environment with Override File

#### docker-compose.yml (Production)
```yaml
version: '3.8'

services:
  app:
    image: myapp:latest
    container_name: production-app
    ports:
      - "8080:8080"
    environment:
      - ENVIRONMENT=production
      - LOG_LEVEL=info
    volumes:
      - app-data:/data
    networks:
      - app-network
    restart: always
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 1G

  db:
    image: postgres:13
    container_name: production-db
    environment:
      POSTGRES_PASSWORD: secure_password_123
    volumes:
      - postgres-data:/var/lib/postgresql/data
    networks:
      - app-network
    restart: always

volumes:
  app-data:
  postgres-data:

networks:
  app-network:
```

#### docker-compose.override.yml (Development)
```yaml
version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "3000:8080"
    environment:
      - ENVIRONMENT=development
      - LOG_LEVEL=debug
      - DEBUG=true
    volumes:
      - .:/app
    command: npm run dev

  db:
    environment:
      POSTGRES_PASSWORD: dev_password
    ports:
      - "5432:5432"
```

#### Commands
```bash
# Start with development overrides
docker compose up -d

# Start with production settings only (ignore override file)
docker compose -f docker-compose.yml up -d

# Start with multiple compose files
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

### Example 5: Using Environment Variables (.env file)

#### .env
```bash
# Database Configuration
DB_USER=appuser
DB_PASSWORD=SecurePassword123
DB_NAME=myapp_db
DB_ROOT_PASSWORD=RootPassword456

# Application Configuration
APP_ENV=development
APP_DEBUG=true
APP_PORT=3000

# Image Tags
NGINX_VERSION=1.24
PHP_VERSION=8.1
MYSQL_VERSION=8.0

# Volume Paths
DATA_PATH_HOST=./data
LOG_PATH_HOST=./logs
```

#### docker-compose.yml
```yaml
version: '3.8'

services:
  nginx:
    image: nginx:${NGINX_VERSION}
    ports:
      - "${APP_PORT}:80"
    volumes:
      - ${DATA_PATH_HOST}:/app

  php:
    image: php:${PHP_VERSION}-fpm
    environment:
      - APP_ENV=${APP_ENV}
      - APP_DEBUG=${APP_DEBUG}
      - DB_USER=${DB_USER}
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_NAME=${DB_NAME}

  mysql:
    image: mysql:${MYSQL_VERSION}
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME}
      MYSQL_USER: ${DB_USER}
      MYSQL_PASSWORD: ${DB_PASSWORD}
    volumes:
      - ${DATA_PATH_HOST}/mysql:/var/lib/mysql
```

#### Commands
```bash
# Docker Compose automatically loads .env file
docker compose up -d

# View resolved variables
docker compose config | grep -A 10 "services:"

# Override specific variables
DB_USER=newuser docker compose up -d
```

### Example 6: Custom Image Building

#### docker-compose.yml
```yaml
version: '3.8'

services:
  web:
    build:
      context: ./webapp
      dockerfile: Dockerfile
      args:
        - BUILD_ENV=production
        - NODE_ENV=production
    image: myapp:latest
    container_name: web-app
    ports:
      - "8080:8080"
    environment:
      - NODE_ENV=production
    depends_on:
      - db
    restart: unless-stopped

  api:
    build:
      context: ./api
      args:
        - BUILD_ENV=production
    image: myapi:latest
    ports:
      - "3000:3000"
    depends_on:
      - db
      - cache
    restart: unless-stopped

  db:
    image: postgres:13
    environment:
      POSTGRES_PASSWORD: password123
    volumes:
      - db-data:/var/lib/postgresql/data

  cache:
    image: redis:7-alpine

volumes:
  db-data:
```

#### Commands
```bash
# Build images before starting
docker compose up -d --build

# Build without starting
docker compose build

# Build specific service
docker compose build web

# Force rebuild without cache
docker compose build --no-cache
```

## Commands Reference

### Basic Commands

```bash
# Start services in background
docker compose up -d

# Start services in foreground (see logs)
docker compose up

# Start specific services
docker compose up -d web db

# Stop services
docker compose stop

# Stop and remove containers
docker compose down

# Remove containers and volumes
docker compose down -v

# View running services
docker compose ps

# View logs
docker compose logs

# View logs of specific service
docker compose logs web

# Stream logs in real-time
docker compose logs -f

# View last 100 lines
docker compose logs -n 100
```

### Service Management

```bash
# Restart services
docker compose restart

# Restart specific service
docker compose restart web

# Scale service to multiple instances
docker compose up -d --scale web=3

# Execute command in running container
docker compose exec web bash

# Execute Python script in service
docker compose exec web python script.py

# Run one-off command
docker compose run web npm install
```

### Building & Images

```bash
# Build images
docker compose build

# Build and start
docker compose up -d --build

# Build without cache
docker compose build --no-cache

# View images
docker compose images
```

### Configuration & Validation

```bash
# Validate compose file
docker compose config

# Show resolved configuration
docker compose config > resolved.yml

# List services
docker compose ps --services

# Show service logs with timestamps
docker compose logs --timestamps
```

### Cleanup

```bash
# Remove all stopped containers
docker compose rm

# Remove without confirmation
docker compose rm -f

# Remove containers, volumes, images, networks
docker compose down --remove-orphans --volumes --rmi all
```

## Best Practices

### 1. **Version Control**
```yaml
# Always pin versions for reproducibility
services:
  db:
    image: mysql:8.0.33  # ✓ Good
    # image: mysql:latest  # ✗ Avoid - unpredictable

  web:
    image: nginx:1.24-alpine  # ✓ Good
```

### 2. **Security**
```yaml
# Don't hardcode secrets in compose file
services:
  db:
    environment:
      # ✗ Bad
      MYSQL_PASSWORD: mypassword123

      # ✓ Good - use .env file or secrets
      MYSQL_PASSWORD: ${DB_PASSWORD}

# Use read-only volumes when possible
volumes:
  - ./config:/etc/config:ro
```

### 3. **Health Checks**
```yaml
services:
  web:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
```

### 4. **Resource Limits**
```yaml
services:
  app:
    deploy:
      resources:
        limits:
          cpus: '1.5'
          memory: 512M
        reservations:
          cpus: '0.5'
          memory: 256M
```

### 5. **Dependency Management**
```yaml
services:
  app:
    depends_on:
      db:
        condition: service_healthy  # Wait until healthy
      cache:
        condition: service_started
```

### 6. **Logging**
```yaml
services:
  app:
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
        labels: "app.service=web"
```

### 7. **Restart Policies**
```yaml
# no - do not automatically restart
# always - restart unless explicitly stopped
# on-failure - restart only on non-zero exit code
# unless-stopped - restart unless manually stopped

services:
  app:
    restart: unless-stopped
  temp-job:
    restart: "no"
  retry-service:
    restart: on-failure:5  # max 5 retries
```

### 8. **File Organization**
```
project/
├── docker-compose.yml           # Main config
├── docker-compose.override.yml  # Local development
├── docker-compose.prod.yml      # Production
├── .env                         # Environment variables
├── Dockerfile                   # Custom image
├── app/                         # Application code
│   ├── src/
│   └── package.json
└── scripts/
    ├── init.sql
    └── entrypoint.sh
```

### 9. **Network Isolation**
```yaml
services:
  frontend:
    networks:
      - frontend-network
  
  backend:
    networks:
      - backend-network
  
  db:
    networks:
      - backend-network

networks:
  frontend-network:
  backend-network:
```

### 10. **Override Files Strategy**
```bash
# Development (default)
docker compose up -d

# Production
docker compose -f docker-compose.yml up -d

# Staging
docker compose -f docker-compose.yml -f docker-compose.staging.yml up -d
```

## Troubleshooting

### Common Issues

```bash
# Service exits immediately
docker compose logs service-name

# Network issues between services
docker compose exec web ping db  # Is DNS resolution working?

# Port already in use
docker compose down  # Stop conflicting containers
# Or map to different port: "9000:8080"

# Permission denied errors
# Run with sudo or add user to docker group
sudo usermod -aG docker $USER

# Volume mount issues on Windows
# Use forward slashes: ./local:/container/path
# Not backslashes: .\local:\container\path

# Service not starting with custom build
docker compose build --no-cache
docker compose up -d
```
