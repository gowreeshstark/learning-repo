# Docker Volumes

## Overview

Docker volumes are used to **persist data** generated and used by containers. By default, data inside a container is lost when the container is removed. Volumes solve this by storing data outside the container's writable layer.

---

## Types of Mounts

| Type | Description |
|------|-------------|
| **Volume** | Managed by Docker; stored in `/var/lib/docker/volumes/`. Best for most use cases. |
| **Bind Mount** | Maps a host directory/file directly into the container. Useful for development. |
| **tmpfs Mount** | Stored in the host's memory only. Data is lost when the container stops. |

---

## 1. Volumes

### Create a volume

```bash
docker volume create my_volume
```

### List all volumes

```bash
docker volume ls
```

### Inspect a volume

```bash
docker volume inspect my_volume
```

### Remove a volume

```bash
docker volume rm my_volume
```

### Remove all unused volumes

```bash
docker volume prune
```

### Use a volume in a container

```bash
docker run -d --name my_container -v my_volume:/app/data nginx
```

Or using the `--mount` flag (recommended):

```bash
docker run -d --name my_container \
  --mount source=my_volume,target=/app/data \
  nginx
```

---

## 2. Bind Mounts

Maps a specific path on the **host machine** into the container.

```bash
docker run -d --name my_container \
  -v /host/path:/container/path \
  nginx
```

Using `--mount`:

```bash
docker run -d --name my_container \
  --mount type=bind,source=/host/path,target=/container/path \
  nginx
```

> **Note:** The host path must exist before running the container.

### Use case
- Sharing source code during development.
- Reading config files from the host.

---

## 3. tmpfs Mounts

Data is stored in the host's memory and **never written to disk**. It is deleted when the container stops.

```bash
docker run -d --name my_container \
  --mount type=tmpfs,destination=/app/temp \
  nginx
```

### Use case
- Storing sensitive data temporarily (e.g., secrets, tokens).
- High-speed ephemeral scratch space.

---

## Volume Sharing Between Containers

Multiple containers can share the same volume:

```bash
docker run -d --name container1 -v shared_volume:/data nginx
docker run -d --name container2 -v shared_volume:/data alpine
```

Both containers read/write to the same `/data` directory.

---

## Key Differences

| Feature | Volume | Bind Mount | tmpfs |
|---------|--------|------------|-------|
| Managed by Docker | Yes | No | Yes |
| Data persists after container stops | Yes | Yes | No |
| Host path control | No | Yes | No |
| Best for production | Yes | No | No |
| Performance | High | Moderate | Very High |

---

## Best Practices

- Prefer **named volumes** over bind mounts in production for portability.
- Use **bind mounts** during development to reflect code changes instantly.
- Use **tmpfs** for sensitive or temporary data that should not be written to disk.
- Always clean up unused volumes with `docker volume prune` to free disk space.
