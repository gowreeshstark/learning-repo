# CDN (Content Delivery Network)

## What is a CDN?
A **Content Delivery Network (CDN)** is a globally distributed network of edge servers that cache and deliver content from locations close to users.

Interview one-liner:
“A CDN reduces latency and origin load by serving cached content from nearby edge locations instead of the primary server every time.”

---

## What CDN caches

Primarily static or semi-static assets:
- Images
- CSS/JS files
- Videos and downloadable files
- Font files
- Public API responses (when cacheable)

CDN can also accelerate dynamic content with rules like:
- Route optimization
- TLS termination
- Edge compute logic

---

## Why location matters

Your note is correct: CDN serves mobile/desktop users based on geography and network proximity.

How it works:
- User request is routed (DNS/Anycast) to nearest CDN PoP (Point of Presence).
- If cached object exists at edge (cache hit), response is instant.
- If missing (cache miss), edge fetches from origin and caches it for next requests.

Benefits:
- Lower latency
- Better user experience globally
- Reduced cross-region bandwidth from origin

---

## Core CDN flow

1. User requests `cdn.example.com/image.jpg`
2. DNS sends user to closest CDN edge
3. Edge checks cache:
	- Hit -> serve immediately
	- Miss -> fetch from origin
4. Edge stores response based on caching headers/policy
5. Future nearby users get fast cached response

---

## “Follows regulations of cache” (HTTP cache rules)

CDN behavior is controlled by cache directives and policies:

Common headers:
- `Cache-Control` (`max-age`, `s-maxage`, `public`, `private`, `no-cache`)
- `ETag`
- `Last-Modified`
- `Expires`

Revalidation behavior:
- Conditional requests (`If-None-Match`, `If-Modified-Since`)
- CDN can validate object freshness with origin before serving stale data

Interview tip:
Mention `stale-while-revalidate` and `stale-if-error` for resilience + performance.

---

## Serving latest content

CDN must balance freshness vs performance.

Techniques:
1. **Versioned asset URLs**
	- e.g., `app.v42.js`
	- safest way to force new content.

2. **Purge/Invalidation API**
	- Remove cached objects immediately.

3. **Short TTL for volatile objects**
	- Useful for frequently changing content.

4. **Revalidation with ETag**
	- Ensure content freshness with low transfer overhead.

## CDN specializations (expanded from your notes)

1. **Edge hosting close to users**
	- PoPs around the world reduce RTT.

2. **Policy and compliance support**
	- Geo restrictions
	- WAF and security controls
	- Data residency/regulatory routing in some providers

3. **Content publishing/management**
	- Push/pull origin models
	- APIs/UI for purge, routing rules, cache keys, TLS certs

---

## CDN and regulations/compliance

Depending on region and industry, design may require:
- Region-aware delivery
- Access control and signed URLs/cookies
- TLS enforcement, HSTS
- Logging and retention policies
- DDoS and bot mitigation controls

Interview-safe phrasing:
“CDN helps enforce delivery and security policies at edge, but data compliance responsibilities still need explicit architecture decisions.”

---

## Cache key design (important interview depth)

CDN decides uniqueness using cache key dimensions such as:
- URL path
- Query params
- Headers (e.g., `Accept-Encoding`, device type)
- Geo/language

Bad cache key design causes:
- Low hit ratio (too many variants)
- Wrong content serving (too few variants)

---

## CDN + origin architecture patterns

### Pull CDN
- CDN fetches from origin on miss.
- Simpler setup, common default.

### Push CDN
- Content pre-uploaded to CDN storage.
- Useful for media-heavy workflows.

### Multi-CDN
- Use multiple CDN vendors for resilience/performance.
- Requires traffic steering and observability tooling.

## Real-time examples

1. **Streaming platform**
	- Video segments cached at edge for global viewers.

2. **E-commerce flash sale**
	- Product images/static assets served from CDN to protect origin.

3. **News portal**
	- Breaking-news pages use short TTL + purge on updates.

4. **Mobile app updates**
	- APK/IPA assets and metadata distributed via CDN globally.

---

## Common CDN pitfalls

1. Long TTL on frequently changing content -> stale pages.
2. No versioning/invalidation strategy.
3. Wrong cache key dimensions.
4. Caching personalized/private responses accidentally.
5. No origin protection -> direct origin abuse bypassing CDN.

---

## Metrics interviewers expect

- Cache hit ratio
- Origin offload percentage
- Edge latency (p50/p95)
- Error rates (`4xx/5xx`)
- Bandwidth savings
- Purge propagation time
