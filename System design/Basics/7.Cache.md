# Cache Memory in Operating Systems

**Reference:** [TakeUForward - What is Cache?](https://takeuforward.org/operating-system/what-is-cache)

## Overview

**Cache memory** is a small, high-speed memory located close to the CPU, designed to store recently accessed instructions and data. It acts as a buffer between the fast CPU and slower main memory, dramatically improving system performance by reducing memory access time.

> **Interview one-liner:** Cache is fast memory that holds frequently used data to speed up CPU access and reduce costly main memory trips.

---

## Definition & Purpose

### What is Cache?
Cache memory is a small, **fast memory unit** that holds **copies of data and instructions** frequently accessed by the CPU. By storing recently used data close to the processor, cache reduces the time for the CPU to retrieve information, thereby enhancing overall system performance.

### Memory Hierarchy
```
             Speed (Fastest)
                  ↑
         ┌─────────────┐
         │   Registers │  (CPU, ~1 cycle)
         └─────────────┘
                ↑
         ┌─────────────┐
         │ L1 Cache    │  (CPU, ~3-4 cycles)
         └─────────────┘
                ↑
         ┌─────────────┐
         │ L2 Cache    │  (CPU, ~10-15 cycles)
         └─────────────┘
                ↑
         ┌─────────────┐
         │ L3 Cache    │  (CPU, ~40-50 cycles)
         └─────────────┘
                ↑
         ┌─────────────┐
         │ Main Memory │  (RAM, ~100-200 cycles)
         └─────────────┘
                ↑
         ┌─────────────┐
         │ Disk/SSD    │  (Very slow, ~ms)
         └─────────────┘
                ↓
             Speed (Slowest)
```

### Size Trade-off
- **Registers:** Fastest, tiniest (bytes)
- **L1/L2/L3 Cache:** Fast, small (KB to MB)
- **Main Memory:** Slower, large (GB)
- **Disk:** Very slow, huge (TB)

## Principle: Locality of Reference

Cache effectiveness is based on the **Principle of Locality**, which states:
> Programs tend to access a **small subset of data and instructions repeatedly**, within a **short time period**.

By placing these active segments in cache, the CPU reduces total execution time.

### Two Types of Locality

#### 1. Temporal Locality (Time)
- Programs repeatedly access the **same memory locations** within a short time period.
- **Example:** Loop variables, frequently called functions.
- **Mechanism:** Keep recently used data in cache.

```
for (int i = 0; i < 1000000; i++) {
    sum += array[i];  // array[i] accessed repeatedly
}
```

#### 2. Spatial Locality (Space)
- CPU accesses **adjacent/nearby memory locations** in sequence.
- **Example:** Array traversal, sequential instruction execution.
- **Mechanism:** Fetch entire cache **blocks** (not just single bytes), knowing neighbors will be accessed soon.

```
int[] array = {...};  // Accessing array[0], array[1], array[2]...
for (int i = 0; i < n; i++) {
    process(array[i]);  // Sequential access
}
```

## Cache Hit vs Cache Miss

When the CPU requests a memory reference:

### Cache Hit ✓
- **Requested data is found in cache**
- CPU retrieves it immediately (fast)
- **Hit time:** Very short (nanoseconds)
- Happens frequently with good cache utilization

### Cache Miss ✗
- **Requested data is NOT in cache**
- Must fetch from lower memory level (main memory, disk)
- **Miss penalty:** High cost (much slower)
- Once fetched, data is placed in cache for future access

### Hit Ratio
```
Hit Ratio = (Number of Cache Hits) / (Total Memory Accesses)
          = Hits / (Hits + Misses)
```

**Example:**
- 95 cache hits out of 100 accesses
- Hit ratio = 95/100 = **0.95 or 95%** (excellent)

**Performance Impact:**
- Higher hit ratio = better performance
- Even small improvements in hit ratio significantly boost speed

## Cache Organization

### Cache Lines
Cache is organized into **cache lines** (not individual bytes).

- Each cache line holds a **fixed number of bytes** (typically 16, 32, or 64 bytes)
- Holds **contiguous data** likely to be accessed together
- When a cache miss occurs, an entire line is fetched from memory
- Exploits **spatial locality** — nearby data is accessed together

### Cache Line Structure
```
┌─────────────────┬──────────┬───────┐
```

## Cache Mapping Schemes

How memory blocks are mapped to cache lines:

### 1. Direct Mapping
- **Each memory block maps to exactly ONE cache line**
- Formula: `cache_line = memory_block % cache_size`
- **Pros:** Simple, fast lookup
- **Cons:** High conflict misses; multiple blocks compete for same line
- **Example:** Block 0, 8, 16... all map to line 0

### 2. Fully Associative Mapping
- **Any memory block can go in ANY cache line**
- Most flexible approach
- **Pros:** Minimizes conflict misses; better hit ratio
- **Cons:** Expensive to implement; slower lookup (must search all lines)
- **Uses:** Typically for small TLBs (translation lookaside buffers)

### 3. Set-Associative Mapping (Most Common)
- **Hybrid of direct and fully associative**
- Cache divided into **sets**; each memory block maps to a specific set
- Within a set, the block can go in any **way**
- **Formula:** `cache_set = memory_block % num_sets`
- **2-way associative:** 2 lines per set
- **4-way associative:** 4 lines per set (common in modern CPUs)
- **8-way associative:** 8 lines per set
- **Pros:** Balance between simplicity and low conflict misses
- **Cons:** Moderate complexity and lookup cost

**Comparison:**
| Scheme | Simplicity | Conflict Misses | Lookup Cost |
|--------|-----------|-----------------|-------------|
| Direct | High | High | Low |
| Fully Associative | Low | Low | High |
| Set-Associative | Medium | Medium | Medium |

## Cache Performance Metrics

### 1. Hit Ratio
```
Hit Ratio = Hits / (Hits + Misses)
```
Target: > 90% for L1, > 95% for L2/L3

### 2. Miss Ratio
```
Miss Ratio = Misses / (Hits + Misses) = 1 - Hit Ratio
```

### 3. Hit Time
- Time to retrieve data from cache (usually 1-10 cycles)
- Very fast, minimal impact on performance

### 4. Miss Penalty
- Time to fetch data from lower memory level
- 10-100+ cycles for main memory
- 1,000,000+ cycles for disk
- Major performance bottleneck

### 5. Average Memory Access Time (AMAT)
```
AMAT = Hit_Time + (Miss_Ratio × Miss_Penalty)
```

**Example:**
- Hit time: 2 cycles
- Miss penalty: 100 cycles
- Miss ratio: 5% (hit ratio 95%)
- AMAT = 2 + (0.05 × 100) = 2 + 5 = **7 cycles**

## Cache Replacement Policies

When cache is full and a new block arrives, which line to replace?

### Common Policies

| Policy | How it works | Pros | Cons |
|--------|-------------|------|------|
| **LRU (Least Recently Used)** | Evict block not used longest | Good hit ratio, follows locality | Complex to implement |
| **FIFO (First In First Out)** | Evict oldest block | Simple | Lower hit ratio than LRU |
| **LFU (Least Frequently Used)** | Evict least accessed block | Good for patterns with frequency | Complex, needs counters |
| **Random** | Evict random block | Simple | Unpredictable performance |
| **Optimal** | Evict block needed furthest in future | Best hit ratio (theoretical) | Impossible to implement (needs future knowledge) |

**LRU is most common** in modern CPUs because it aligns with temporal locality principles.

## Factors Improving Cache Performance

### 1. Increasing Cache Size
- **More capacity** for frequently used data
- **Trade-off:** Larger cache → higher latency
- Diminishing returns; even doubling size may not halve miss rate

### 2. Increasing Associativity
- **Set-associative** > Direct mapped
- Reduces conflict misses
- **Trade-off:** Higher associativity → slower lookup

### 3. Increasing Block/Line Size
- **Larger blocks** exploit spatial locality better
- Prefetches adjacent data
- **Trade-off:** Too large → waste space, longer fetch time
- Optimal: 32-64 bytes (typical modern CPUs)

### 4. Reducing Miss Penalty
- **Multi-level caches** (L1 → L2 → L3 → memory)
- **Prefetching** — anticipate needed data
- **Write buffering** — delay writes to memory

### 5. Reducing Hit Time
- **Simpler cache design** (direct mapped)
- Smaller cache (paradoxically faster)
- **Trade-off:** May increase miss rate

### 6. Multiple Cache Levels (L1, L2, L3)
- **L1:** Small, fast (4-32 KB)
- **L2:** Medium (256 KB - 1 MB)
- **L3:** Large (4-20 MB), shared by cores
- **Strategy:** Exploit all three for performance

## Cache Write Policies

How to handle data writes to cache?

### 1. Write-Through
- Write data to **both cache and memory immediately**
- **Pros:** Data always consistent between cache and memory
- **Cons:** Slow; every write goes to slow memory

### 2. Write-Back (Write-Defer)
- Write data only to **cache**, mark as "dirty"
- **Later:** Write to memory when line is evicted
- **Pros:** Fast; reduces memory traffic
- **Cons:** Complex; risk of data loss if cache fails

**Modern systems typically use Write-Back** for performance.

## Interview Quick-Fire Q&A

**Q: What is cache and why is it needed?**
Cache is fast memory near the CPU that holds frequently accessed data, dramatically reducing memory access time.

**Q: Explain locality of reference.**
Programs tend to access the same/nearby data repeatedly within short time periods (temporal + spatial).

**Q: Cache hit vs cache miss?**
Hit = data found in cache (fast); Miss = data not in cache (slow, must fetch from memory).

**Q: How is cache hit ratio calculated?**
Hit Ratio = Hits / (Hits + Misses)

**Q: What are cache lines?**
Fixed-size blocks (typically 16-64 bytes) that hold contiguous data; exploits spatial locality.

**Q: Difference between direct-mapped, fully associative, and set-associative?**
Direct: one block → one line (simple, conflicts). Fully: any block → any line (flexible, slow). Set: balance (common in modern CPUs).

**Q: Why use multiple cache levels (L1, L2, L3)?**
Each level is increasingly larger/slower, providing progressive fallback while keeping L1 fast.

**Q: Write-through vs write-back?**
Write-through: write to cache+memory (slow but safe). Write-back: write cache only, flush later (fast, risky).

**Q: How does cache improve performance?**
By exploiting locality, keeping hot data close to CPU, reducing average memory access time.

## Key Takeaways

- **Cache** = fast memory exploiting **locality of reference**.
- **Hit Ratio** is the key performance metric; higher is better.
- **Temporal locality:** Reuse same data soon.
- **Spatial locality:** Nearby data accessed together.
- **Cache lines** fetch blocks, not bytes (spatial locality).
- **Three mapping schemes:** Direct (simple), Fully Associative (flexible), Set-Associative (balanced).
- **L1/L2/L3 caches** provide multi-level fallback for performance.
- **Write-back** typically used over write-through for speed.
- **Modern CPUs:** 4-way set-associative, 32-64 byte lines, multiple levels.
